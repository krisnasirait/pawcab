## Findings

### 1. MEDIUM — Shared header/footer fonts change by route

Rule R-06 typography; design-system consistency.

Sources: `src/app/globals.css:48–79`, `src/app/page.tsx:27`, `src/components/Header.tsx:62`, `src/components/Footer.tsx:20`.

On home, Header/Footer are descendants of `main[data-ui="public"]`, so their `.font-display` aliases resolve to Cormorant. On all four subpages they are siblings of main, outside the repaired alias scope, and inherit Public Sans. This is visible in both development and production computed styles. Outside the scope, unweighted chrome text also inherits body defaults (300 / 1.35) instead of the public defaults (400 / 1.55).

Recommended fix: establish one public typography boundary that includes shared chrome, or resolve the needed family/public text defaults locally in Header/Footer. Keep admin/login separate; do not globally change body to solve this.

### 2. MEDIUM — Some public serif controls request weights that are not loaded

Rule R-06 typography; plan's supported 400/500 display weights.

Sources: `src/app/layout.tsx:9–14` loads Cormorant 300/400/500 only; `src/components/PetTransportPricing.tsx:491` requests `font-extrabold` (800) for total fare; `src/components/MapPickerModal.tsx:218` requests `font-bold` (700) for the map heading.

These are source-confirmed populated-estimator/modal states, not part of the idle-route heading snapshot. They resolve to the serif within public scope, but cannot obtain actual 700/800 faces from the configured files; browser weight matching/synthesis substitutes for the requested design. The estimator also uses display serif for distance/rate/total, contrary to DESIGN.md's body-family numeral role; revised walking prices already use body numerals.

Recommended fix: use Public Sans with tabular numerals for functional fare values; use supported 400/500 serif weights for dialog/display headings. Do not add more font files merely to preserve accidental utility weights.

### 3. LOW — Booking-step headings retain the old thin, tight treatment

Rule R-06 typography; new public display-weight standard.

Source: `src/components/HowItWorksSection.tsx:56`.

All four booking-step H3s compute to Cormorant 300 at 20px with 19px line height on desktop and phone. Explicit `font-light` overrides the scoped 400 default, while missing local leading inherits the legacy global 0.95 heading line height. These are smaller and more fragile than the revised display treatment.

Recommended fix: use 400 (or Public Sans 500 for compact utility headings) with an explicit comfortable line height around 1.2–1.3. Preserve titles and sequence.

### 4. LOW — Estimator heading line height remains below the new type specification

Rule R-06 typography.

Sources: `src/components/PetTransportPricing.tsx:216`; legacy fallback in `src/app/globals.css:101–104`.

“Zone rates, measured live.” computes to 52px / 49.4px on desktop and 36px / 34.2px on phone (0.95). Adjacent marketing section titles use roughly 1.05–1.08. The estimator is shared by home and transport, so this compressed exception repeats across two pages. No actual clipping was established; the issue is inconsistent multiline rhythm and poor tolerance for longer CMS content.

Recommended fix: explicit leading around 1.05–1.1 for this heading. Avoid raising every global heading indiscriminately, particularly admin/login.

### 5. LOW — Important form text uses a substantially smaller scale than other booking UI

Rule R-06 typography; readability quality issue, not a claimed WCAG minimum-font-size failure.

Sources: `src/components/AddressSearchInput.tsx:141,261–266,318`; `src/components/PetTransportPricing.tsx:335–353,417–459,523`; FAQ question spans in all three FAQ components.

Examples: pickup/drop-off and notes labels are 12px; address attribution/detail text 11px; textarea is 12px on phone; populated fare-detail labels are 11px. FAQ questions use Cormorant 16px on phones while answers are sans 14px. The core page body is 17–18px, making essential booking text noticeably finer. Some 11px metadata is justified; the recommendation is not to enlarge every caption uniformly.

Recommended fix: distinguish three roles consistently: body 16–18px, essential labels/controls 14–16px, secondary metadata 12–13px. Consider sans 500 or a larger serif for FAQ questions. Keep legal attribution secondary and preserve all text.

## Passing checks and limitations

- H1s across all five public pages consistently use Cormorant 400; the earlier subpage H1 fallback is fixed.
- Public main body copy does not inherit 300 in the sampled paragraphs/list items, aside from explicit exceptions identified above.
- No horizontal document overflow at 320/390/1440 in the sampled idle routes, development or production.
- Production build succeeded. No application edits made for this audit.
- Login's sans heading is existing behavior deliberately preserved in audit 004, not automatically a defect requiring a redesign. Authenticated admin source contains legacy serif utility classes and system-sans workspace styles; its rendered state remains unverified.
- Populated route results, autocomplete option states, map modal and third-party widget interiors were source-reviewed where mentioned, not exhaustively browser-tested in this audit. No explicit 200% text-resize pass or font-performance claim is made.

Suggested repair order: #1 and #2 first, then #3–#5 as one scoped typography consistency pass. Owner approval required before application changes.
