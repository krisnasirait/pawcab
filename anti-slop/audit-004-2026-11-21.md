## Numbered findings

### 1. HIGH — All four subpage desktop hero grids have only one child

Rules: C-3/C-4 (content composition/resilience); plan §8 requires text/media columns.

Files: `src/app/services/pet-transport/page.tsx:75-152`, `src/app/services/dog-walking/page.tsx:78-152`, `src/app/services/pet-sitting/page.tsx:105-180`, `src/app/stories/page.tsx:71-135`.

The wrapper opened for breadcrumb and text is not closed before the photo wrapper. Thus `grid lg:grid-cols-2` contains one child with both text and photo. At 1440 px, all four photographs start at x=80, below their text (y≈522–581), while the right-hand column is empty. Walking and sitting images touch the CTA row with no separate grid gap.

Fix scope: make the text wrapper and photo wrapper siblings, retaining copy, image sources and mobile source order. Recheck all four routes at desktop and phone sizes.

### 2. MEDIUM — Legacy font utilities resolve to invalid aliases and inherit body sans

Rules: C-1 intentional typography, C-4 cross-route consistency; plan §5 typography.

File: `src/app/globals.css:48-58`; affected `.font-playfair` headings throughout service pages, stories, pricing and FAQs.

Production computed H1 family on all four subpages is Public Sans, not Cormorant Garamond. `--font-cormorant` is present on body, but computed `--font-playfair` and `--font-display` are empty. The aliases are declared in root-level `@theme` while their Next font source variables are supplied on body. The utility-layer `font-family: var(--font-playfair)` overrides the base heading rule, becomes invalid at computed-value time and inherits the body family. Home H1 avoids that utility and correctly renders Cormorant.

Fix scope: resolve font aliases where their source variables exist (or use Tailwind inline font mappings/direct resolved families); verify computed styles in a fresh production build, including admin/login compatibility.

### 3. HIGH — Gallery modal neither contains nor restores keyboard focus

Rule: R-32 keyboard accessibility; plan §9 and acceptance matrix explicitly require containment/restoration.

File: `src/components/GallerySection.tsx:26-41` and modal markup at :102 onward.

Reproduction: open a passenger photo; close button initially receives focus. Press Tab three times: focus leaves the dialog and lands on the page's “Chat on WhatsApp” link behind the overlay. Escape closes the dialog but leaves focus on that background link rather than returning to the photo trigger. Body scroll locking and `aria-modal` do not prevent background keyboard access.

Fix scope: contain modal focus, make background noninteractive while open, restore the invoking photo button on every close path. Also check previous/next actions do not reset focus unnecessarily.

### 4. HIGH — Map picker also permits keyboard focus behind its modal

Rule: R-32 keyboard accessibility; plan §7/§9 modal requirements.

File: `src/components/MapPickerModal.tsx:102-117`.

Reproduction in production: open “Choose on Map”, then Shift+Tab from the initially focused close button. Focus escapes to a background IFRAME. The effect handles Escape, scroll locking and opener restoration but contains no focus trapping/background inertness.

Fix scope: implement dialog containment without breaking Leaflet controls or opener restoration; verify forward/backward Tab and Escape on mobile/desktop. This is an unresolved existing behavior in a component included in migration acceptance, not an independently established new regression.
